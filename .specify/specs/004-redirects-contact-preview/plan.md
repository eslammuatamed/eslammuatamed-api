## Summary

Three modules over existing tables + reserved permission keys: (1) **redirects** — a public `GET /redirects/resolve` plus auto-creation of `SlugRedirect` rows when a **published** article/project locale-slug changes (written in the same DB transaction as the rename); (2) **contact** — a public throttled `POST /contact` with honeypot + time-trap anti-spam, plus a `messages.*`-guarded admin inbox (list/detail/read/archive, no reply); (3) **preview** — dedicated per-type HMAC token **mint** endpoints (`POST /admin/{articles,projects}/{id}/preview-token`) and public **consuming** routes (`GET /preview/{articles,projects}/{id}?token=`) that return drafts and `404` any bad/expired token. All additive to `/api/v1` (D10-1) → minor OpenAPI bump.

## Decision — Redirects: resolve + auto-on-rename (D10-7, D04-6)

- **`RedirectsModule`** exports **`RedirectService`** with two methods:
  - `resolve(locale, path): Promise<{ toPath } | null>` — validates `locale` (`LocalesService.assertEnabled`), maps the **website** path to `(entityType, fromSlug)` via the grammar below, looks up `SlugRedirect` on the `@@unique([locale, entityType, fromSlug])` key, returns `{ toPath }` or `null` (→ controller 404). **One hop** (no transitive walk).
  - `buildRedirectOps(tx-args): Prisma.PrismaPromise[]` — returns the redirect-create operation(s) to **push into the caller's existing `$transaction` array** (articles/projects already use the array-batch `$transaction` form), so the redirect and the slug change commit atomically. Signature designed so `articles`/`projects` call it inside `update()` without a nested transaction.
- **Path/section grammar (OQ-5, pinned):** operates on **website** paths (the front-end's, independent of the API's own `/articles` route). Section → `entityType`: `/blog/{slug}` → **`article`**, `/projects/{slug}` → **`project`**. `entityType` stored values: **`article`**, **`project`** (OQ default, pinned). `toPath` = `/{section}/{toSlug}`. Unknown section or no record → `null`/404. `?path` is section-relative; `locale` is the explicit param (front-end strips the `/ar` prefix, doc 04 §2).
- **Auto-create hook (D04-6):** inside `ArticlesService.update()` (articles.service.ts:323) and `ProjectsService.update()` (projects.service.ts:191): diff each incoming `dto.translations[].slug` against `existing.translations[locale].slug`. **Predicate — the old slug must have been publicly live AND the new slug must stay publicly live** (a redirect only makes sense to preserve a URL that existed and points at one that resolves): articles `existing.status === PUBLISHED && nextStatus === PUBLISHED` (`nextStatus = dto.status ?? existing.status`, already computed at articles.service.ts:329); projects `existing.isPublished === true && nextIsPublished === true` where `nextIsPublished = dto.isPublished ?? existing.isPublished` — **`ProjectsService.update()` currently discards `getAdminOrThrow(id)` (projects.service.ts:192); capture it as `const existing = …`** to read the old slugs *and* `existing.isPublished` (articles already captures `existing` at :324). This gate correctly skips draft→publish+rename (old slug never public → nothing to preserve) and publish→unpublish+rename (new slug not live → redirect target would 404). When the predicate holds **and** the slug changed (`old !== new`), push these **three** operations (per changed locale) into the same `operations[]` array **before** `$transaction`, so all commit atomically with the rename:
  1. **Collapse chains** — `slugRedirect.updateMany({ where: { locale, entityType, toSlug: old }, data: { toSlug: new } })`: any prior redirect that pointed at the now-vacated `old` slug is repointed at `new`, so every redirect stays **one hop to the current live slug** (avoids `a→b→c` chains / 301-chain SEO penalty).
  2. **Clear stale source** — `slugRedirect.deleteMany({ where: { locale, entityType, fromSlug: new } })`: the `new` slug is now **live**, so it must not also be a redirect source (this is the correct per-slug invariant — the table is slug-keyed, not entity-keyed — and is what makes rename-back `b→a` and slug-reuse safe: when `a` becomes live again, its stale `a→*` row is removed).
  3. **Record** — `slugRedirect.create({ data: { locale, entityType, fromSlug: old, toSlug: new } })` (or upsert on the unique key).
  Skip entirely for draft/scheduled/archived entities, unchanged slugs, and `old === new`. **Invariant:** a live published slug is never a redirect `fromSlug`; no redirect is self-referential; resolution never cycles. *(These edge cases — rename-back, slug-reuse across entities, `a→b→c` chain collapse, per-locale isolation — are explicit `tasks.md` test cases, not prose.)*
- **No `/admin/redirects` CRUD** (owner). The public `resolve` route is `@Public()`, `@Throttle` public tier. **Caching (override, not the doc 10 §5 default):** unlike other public GETs, `resolve` sets **`Cache-Control: no-store`** (or a very short max-age) — D10-7's own rationale is that "redirects are runtime data," and edge-caching a **miss** for 60s would mask a just-created redirect (defeating auto-on-rename). This carve-out is noted in the T1 doc 10 amendment so §5's blanket cache statement doesn't contradict it.
- **Circular-dep avoidance:** `ArticlesModule`/`ProjectsModule` import `RedirectsModule` (exported `RedirectService`); `RedirectsModule` imports neither → no cycle. `RedirectsModule` imports `LocalesModule` for `assertEnabled`.

## Decision — Contact: intake + anti-spam + inbox (FR-PUB-050/051/052, FR-DSH-060, D02-1/4, doc 19 §6)

- **`ContactModule`**: `contact.controller.ts` (public `POST /contact`), `messages.admin.controller.ts` (`/admin/messages`), `contact.service.ts`, `dto/`, `entities/`, anti-spam helper.
- **Intake `POST /contact`** `@Public()`: `CreateContactMessageDto` = `name`, `email` (`@IsEmail`), `subject`, `body` (all length-capped, whitelisted) **+** the honeypot `website` and time-trap `elapsedMs` fields (request-only, **not** persisted). Persists `ContactMessage` with `meta = { userAgent, referrer }` (from request headers; absent → `{}`). Success → `{ data: { id } }` (or a minimal receipt). `422` + `errors[]` on invalid input. **Validation-pipe interaction (must-get-right):** the global pipe is `whitelist + forbidNonWhitelisted + transform`, so `website`/`elapsedMs` **must be declared** in the DTO (else an unknown property → 422 = a distinguishable signal) **and validated permissively** — `website: @IsOptional() @IsString()` (**no** `@MaxLength` that could reject), `elapsedMs: @IsOptional() @IsNumber()` (**no** `@Min`) — so a filled honeypot or a sub-threshold `elapsedMs` reaches the **service** and is dropped-as-success (2xx), never rejected by the pipe with a 422 that leaks the trap (FR-004-02).
- **Anti-spam (OQ-6, pinned; shared web/API contract, D02-1):** honeypot field **`website`** (a real form keeps it hidden/empty; any non-empty value ⇒ **drop-as-success**). Time-trap field **`elapsedMs`** — the **client-computed** milliseconds between form render and submit (an elapsed duration, **not** an absolute timestamp — so a client with a skewed/behind clock is never falsely dropped on the platform's single conversion point, D05-4); if `elapsedMs < MIN_FILL_MS` (**3000 ms**) or is absent/negative ⇒ **drop-as-success**. "Drop-as-success" = return the same 2xx receipt shape but **persist nothing** (no bot signal). Both fields are request-only (never persisted), documented so the Nuxt form matches; acknowledged as a lightweight, spoofable-but-cheap layer backed by the IP rate limit (D02-1 chose this over CAPTCHA).
- **Throttle `POST /contact` = 3/hour + 10/day per IP (doc 19 §6):** implemented as a **route-local two-window throttler guard** (`@UseGuards` on the intake route), mirroring the shipped `upload-user-ip-throttler.guard.ts` precedent — **not** globally-registered named throttlers (which would apply to every route). Keyed by **IP**, reusing the **trusted-IP extraction** from `upload-user-ip-throttler.guard.ts` (production runs behind `trust proxy`, so the tracker must read the proxy-resolved client IP, not a spoofable header). Two windows: hourly `{ttl: 3_600_000, limit: 3}` + daily `{ttl: 86_400_000, limit: 10}` added to `THROTTLE_TIERS` as `contactHourly`/`contactDaily`. Excess → RFC 7807 `429` + `Retry-After`. Exact `@nestjs/throttler` wiring confirmed against current docs during implementation (nestjs-mentor).
- **Inbox `/admin/messages`** (class `@Throttle admin`, `@ApiBearerAuth`, default-deny): `GET /admin/messages` (`messages.read`) — paginated `PaginationQueryDto` → `{data, meta}`, **unread-first** default sort (`ORDER BY isRead ASC, createdAt DESC`, backed by `@@index([isArchived, isRead, createdAt])`), filters `isRead`/`isArchived`; `GET /admin/messages/{id}` (`messages.read`); `PATCH /admin/messages/{id}` (`messages.update`) — `UpdateMessageDto { isRead?, isArchived? }`. **No** `messages.create` route, **no** reply (D02-4). Admin reads return the full record (not locale-resolved — messages are locale-agnostic).

## Decision — Preview tokens: util + mint + consume (D10-8, D10-11, D19-7)

- **Token util (`PreviewTokenService`)** reusing **D19-7 verbatim**: `mint(entityType, entityId): { token, expiresAt }` where `exp = now + 30 min`, `mac = HMAC_SHA256(previewTokenSecret, ` `${entityType}:${entityId}:${exp}` `)`, wire format **`base64url(exp).base64url(mac)`**; `verify(entityType, entityId, token): boolean` recomputes the MAC and `crypto.timingSafeEqual`-compares, then checks `exp` not passed. **Robustness:** `timingSafeEqual` **throws on length-mismatched buffers**, and `exp`/base64url parsing can fail on a malformed token — `verify` wraps all of this and returns `false` (never throws), so a garbage `?token=` maps to `404`, never a `500`. `previewTokenSecret` from `AppConfigService.auth.previewTokenSecret`. **Token values never logged.** No DB state.
- **Mint endpoints (D10-11):** `POST /admin/articles/{id}/preview-token` (`@RequirePermission('articles.update')`) + `POST /admin/projects/{id}/preview-token` (`@RequirePermission('projects.update')`). Assert the entity exists (else the admin 404 convention). Return `{ data: { token, url, expiresAt } }` with `@Header('Cache-Control', 'no-store')`. **`url` semantics (owner-resolved 2026-07-20 → D10-11 v1.4.1):** `url` is an **absolute rendered-Web URL** — `${PUBLIC_WEB_URL}/preview/{articles|projects}/{id}?token=<token>` — the dashboard shares **verbatim** as a clean-browser reviewer link (**the API signs, the Web renders**; the rendered Web page then calls the consuming `GET /api/v1/preview/…` API route, D10-8). This makes the preview story **cross-repo**: the Web app adds the rendered `/preview/{articles,projects}/{id}?token=` routes. `PUBLIC_WEB_URL` is a **dedicated** config (canonical public site origin), never `CORS_ORIGIN`; validated absolute http/https, dev-default `http://localhost:3000`, **required in production** (stop-gate). `token` is also returned separately. Mint lives on `PreviewModule`'s admin controller, which injects `AppConfigService` + the exported `ArticlesService`/`ProjectsService` for existence checks (no cycle). Never embed tokens in any GET/list response; token/url never logged.
- **Consuming routes (D10-8):** `GET /preview/articles/{id}?token=` + `GET /preview/projects/{id}?token=`, `@Public()`, `@Header('Cache-Control','no-store')`. Flow: `PreviewTokenService.verify('article', id, token)` → on failure **`404`** (draft invisibility, FR-PUB-046 — never 401/403); on success call `ArticlesService.getPreviewById(id, locale)` (new status-agnostic method reusing `resolveDetail()`), `404` if the entity truly doesn't exist. A token for the wrong type/id fails `verify` (the MAC binds `entityType:entityId`). `?locale` validated as elsewhere.
- **New service methods:** `ArticlesService.getPreviewById(id, locale)` + `ProjectsService.getPreviewById(id, locale)` — reuse the existing status-agnostic `resolveDetail()`, keyed by `id`, **bypassing** the `status`/`isPublished` public filter. Exported for `PreviewModule` (which imports `ArticlesModule`/`ProjectsModule`).
